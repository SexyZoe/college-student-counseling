# 辅导员数据库发布与回退

网页入口分为管理员和辅导员两种角色，包含学生登记、Excel 导入导出、月度等级、谈话记录、一级学生周台账、班级心理委员、降级出库申请与假期离校统计。管理员可浏览、预览、打印和导出各辅导员数据，业务写入接口统一禁止管理员修改；账号和教学日历管理仍向管理员开放。

## 数据与依赖

- MySQL 008—014 迁移仅新增业务表，不删除历史业务表。已经运行 009 的校园实例只需追加 010—014。
- 保留现有 `.env`、`compose.override.yaml`、数据库及媒体卷和原数据加密密钥。不要上传或替换本机测试数据库。
- 后端镜像内置 LibreOffice Writer、Calc、Poppler 和中文字体，构建时检查 Calc 与图片渲染器可用。预览和打印使用实际 PDF；Excel 使用去除样本个人信息的学校原表模板。假期截图按单元格范围和原比例嵌入，提供清晰排版和原表列宽选项。
- 后端 `/tmp` 为 256 MiB 的临时内存文件系统，用于生成文档及预览，转换完成后清理。校园离线 APK 缓存也必须包含 Calc、Poppler 及其依赖；不能沿用缺少这些工具的旧缓存。
- 空库初始化与重复迁移在隔离 MySQL 验证；业务验收脚本会写入虚构记录，只能对隔离库运行：`CONTRACT_TEST_ALLOW_WRITES=true npm --prefix server run contract:test`。覆盖全部新表单、实际 Excel/PDF 预览、截图导出及管理员只读。旧测评契约脚本不再用于本版发布。

## 发布步骤

1. 记录 Git 提交、正在运行容器的实际镜像 ID 和 Compose 项目目录；镜像标签可能已经移动，不能仅记录标签。
2. 在现有实例运行 `bash deploy/mysql-backup.sh`，校验数据库及媒体加密备份的 SHA-256，并为当前实际镜像添加独立回退标签。
3. 从已提交版本的 `git archive` 建立新发布目录，复制原实例配置，将 `backups` 链接到现有备份目录。保留 `shuzhi-heart-harbor` Compose 项目名以复用已有卷。
4. 构建 `backend-mysql` 和 `mysql-migrate` 镜像。在替换业务服务前，使用候选镜像，在独立 MySQL 容器和独立数据库中检查迁移、权限、登记导入、全部表单保存和实际文档预览导出。
5. 对现有 MySQL 执行迁移。MySQL 保持运行，先启动并等待新后端健康，再更新网关。此为单实例切换，可能短暂中断。
6. 检查网关 `/ready`、`/web/`、两个角色登录、权限隔离和导出转换服务。保存当前提交和发布目录，核对既有用户及历史业务记录数量。

## 回退

停止更新后的后端，使用步骤 1 的旧镜像和旧 Compose 配置重新启动后端及网关。新增表继续保留；不删除卷、不反向删除迁移、不自动覆盖在线数据库。需要恢复数据时另行停写并核对备份目标。

学校现有地址为 `http://172.18.132.12/web/`。功能发布沿用校园现有网络配置；HTTP 地址不具备 HTTPS 传输保护。若要切换生产配置，应先提供可用校园域名、证书及数据库 CA，再按生产部署手册验收，不能仅把 `NODE_ENV` 改成 `production`。
