# 学校与专业审核待办清单

以下内容无法由代码自行决定，需要学校、业务部门或心理专业人员提供书面答复。获得信息前，项目继续使用虚构数据。

## 学校信息中心

- 最终部署位置：学校服务器或华为云；
- Linux/容器平台、CPU、内存、磁盘和扩缩容方式；
- MySQL或RDS版本、连接地址、TLS CA、账号权限和连接上限；
- 测试、预发布、生产三套环境是否可独立提供；
- 小程序HTTPS域名、证书、DNS备案、网关、WAF和出口策略；
- 是否支持OIDC、OAuth 2.0、CAS或其他统一认证，并提供测试环境参数；
- 学生、班级、辅导员、学期数据API文档、测试凭据、字段字典和更新频率；
- 日志平台、Prometheus/云监控、告警渠道和7×24应急联系人；
- 备份保留时间、跨区域要求、RPO/RTO和恢复审批流程；
- 等保、渗透测试、代码审计、数据出境和第三方测评要求；
- 数据保留、归档、删除和学生权利请求处理规则。

## 学工与心理专业部门

- 量表名称、版权/授权证明和允许使用范围；
- 问卷版本、评分版本、反向题、阈值和关键题的书面审核；
- “关注、较高风险、紧急风险”的业务含义，避免等同医疗诊断；
- 风险事件通知对象、响应时限、升级路径、夜间和节假日机制；
- 辅导员能查看的最小字段和禁止查看的原始数据；
- 学生知情同意、隐私政策、未成年人场景和撤回机制；
- 科普与课程思政内容的发布、审核、下架和责任人；
- 报表、导出、水印、审批与留痕要求；
- 紧急求助电话和校内支持资源的准确内容。

## 项目负责人需要确认

- GitHub分支保护和至少一人审核规则；
- 开发成员的职责、生产访问权限和离职权限回收；
- 上线日期、试点学院、学生范围和灰度计划；
- 预算、云资源采购、短信/通知渠道和安全测评费用；
- 最终业务验收人、技术验收人和发布批准人。
