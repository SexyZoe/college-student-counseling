# 校园云部署验收记录

验收日期：2026-09-17。目标：把已有微信小程序后端和数据库部署到学校提供的云实例，形成可复现、可运维、可展示的云计算项目。

## 本次实施

- 在学校 Ubuntu 实例运行 Docker Compose：Nginx、Node.js 后端、MySQL 8.4；不是额外申请托管数据库。
- 网关统一提供 80 端口；后端仅在宿主机回环地址发布；数据库不发布宿主机端口。
- MySQL 数据卷持久化，多阶段应用镜像，独立迁移任务与健康依赖。
- Docker 日志轮转、自动重启、每分钟就绪/指标检查、每日加密逻辑备份。
- 在隔离容器执行恢复演练，验证备份可解密并导入。
- 小程序默认切换校园云地址，认证成功后才建立本地页面会话，网络失败不降级成演示登录。

## SSH 故障根因与修复证据

原项目网络为 `172.19.0.0/16`，而 Mac 校园地址为 `172.19.30.8`。实例执行 `ip route get 172.19.30.8` 指向 Docker 网桥，说明返回客户端的报文走错接口。VPN 还曾使本机访问实例的路由转向 TUN，因此单纯 TCP 端口成功不足以证明 SSH 握手成功。

将项目容器网络显式改为 `192.168.240.0/24` 后重建网络，保留原 MySQL 数据卷，移除临时客户端 `/32` 路由。实例复查结果：

```text
172.19.30.8 via 172.18.132.1 dev ens3 src 172.18.132.12
Docker network: 192.168.240.0/24
```

Mac 通过 `en0` 的 SSH 与网关请求均成功。这证明本次返回路径冲突已排除，不代表所有校园网段或 VPN 配置都已经验证。

## 可以写进简历的内容

**数智心港湾｜校园云实例上的容器化心理健康小程序后端**

- 基于学校云实例搭建 Nginx + Node.js + MySQL 容器化服务，使用 Docker Compose 管理依赖、持久化卷、健康检查及数据库迁移，完成三角色小程序后端接入。
- 排查 Docker 地址池与校园网重叠导致的 SSH 回程路由故障，通过路由分析和显式子网规划恢复访问。
- 编写可重复发布、MySQL 加密备份及隔离恢复脚本，结合 systemd 定时检查和结构化日志形成基础运维流程；恢复演练验证 14 张业务/迁移表可导入。
- 修复云端认证与本地会话不一致问题，补充登录失败、网络超时、非法会话和角色不匹配回归测试。

不要写成 Kubernetes、高可用、自动扩缩容、异地容灾、完整监控告警平台或真实学生生产上线；这些尚未实现。压测仅为小样本健康接口验证，不建议把该数值写成系统承载能力。
