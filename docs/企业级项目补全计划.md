# 数智心港湾企业级项目补全计划

> 版本：1.0
>
> 更新日期：2026-08-14
>
> 目标：将当前可演示的小程序原型逐步建设为可测试、可部署、可审计、可恢复、可交接的校级应用。
>
> 安全边界：学校审批和专业审核完成前，只使用虚构或脱敏测试数据。

## 二、企业级完成标准

只有同时满足以下条件，项目才能定义为“正式可上线”：

1. 所有代码通过Pull Request、自动化测试和代码审核进入`main`。
2. 测试、预发布和生产环境相互隔离，密钥和真实数据不进入Git仓库。
3. 生产数据库使用MySQL或学校认可的关系型数据库，具备迁移、备份和恢复能力。
4. 学生、辅导员和管理员权限在服务端执行，任何客户端参数都不能扩大访问范围。
5. 心理答案、评分结果和风险记录按照敏感个人信息要求保护。
6. 学校统一认证、学生组织数据和学期数据有可靠来源及同步审计。
7. 风险事件有专业复核、通知、跟进、升级和关闭流程。
8. Android、iPhone、弱网、断网恢复和集中交卷场景通过验收。
9. 生产环境具备HTTPS、日志、监控、告警、限流、备份及应急恢复。
10. 心理专业、隐私合规、学校业务部门和信息中心完成书面验收。

## 六、近期执行顺序

1. 将M0、M1与本轮安全/运维基线通过PR合并，保留`project.config.json`个人配置在本地。
2. 同步向学校收集M3、M4和M6所需资料，优先取得数据库TLS、API和统一认证测试参数。
3. 在虚构数据环境继续补全M2的风险通知、导出治理和账号生命周期通用框架。
4. 学校资源到位后先部署测试环境，执行MySQL恢复、综合压力和真机联调。
5. 任何时候都不直接用生产数据试错。

## 七、变更管理原则

- 每个里程碑使用独立`codex/`或`feature/`分支；
- 一次PR只解决一个清晰目标，禁止把个人配置和无关修改混入；
- 合并前必须通过自动化测试、容器构建和至少一名成员审核；
- 数据库结构只通过迁移文件修改，不在生产环境手工改表；
- 密钥只进入部署平台的密钥管理或环境变量，不写入代码和文档；
- 生产变更必须有备份、回滚步骤、负责人和验证记录。
